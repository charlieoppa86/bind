# BIND 정보구조도 (IA)

- 작성일: 2026-11-15 (2026-11-16 개정: 장소 자유 입력 체크인 — 위치·PIN·체류 시간 없음. 아래 "개정 내역" 참고)
- 근거 문서: BIND 최상위 전략 문서, BIND 사용자 스토리 (Must 12 · Should 7)
- 하단 탭 4개: **스팟 · 신청함 · 채팅 · 마이**. 체크인 전에는 스팟 탭 대신 체크인 흐름이 먼저 열린다.
- POP = 다이얼로그, 시트 = 바텀시트. 둘 다 별도 라우트를 갖지 않는 오버레이는 기능 칸에 적고, 독립 라우트가 필요한 것만 행으로 뺐다.
- 용어: 문서의 "스팟"은 사용자가 입력한 장소다. 같은 장소 이름(띄어쓰기·대소문자 무시)을 입력한 사람끼리 같은 스팟 피드를 본다.

## 누락/중복 검토

- **누락된 스토리: 없음.** Must 12개와 Should 7개가 모두 1개 이상의 경로에 매핑된다.
- **앱 라우트가 없는 스토리: US-018.** 주최자 리포트는 MVP 단계에서 운영자가 이메일로 보낸다. 주최자용 앱 화면이 필요해지면 `운영` 분류를 별도 웹 대시보드로 분리한다.
- **Could 스토리(US-020~023)는 매핑하지 않았다.** 추가할 때 위치는 다음과 같다. US-020 부스트 → 스팟 > 스팟 피드 > 내 체크인. US-021 명함 보내기 → 채팅 > 대화방. US-022 인기 키워드 → 스팟 > 스팟 피드. US-023 주최사 로고 → 스팟 > 스팟 피드 헤더. 새 라우트는 생기지 않는다.
- **중복된 경로: 없음.** 다만 진입점이 여러 개인 화면이 3개 있으며, 모두 의도한 것이다.
  - 사용법 가이드: 온보딩과 마이에 라우트가 2개 있지만 같은 위젯을 재사용한다.
  - 신고·차단: 스팟 피드, 신청 상세, 대화방 3곳에서 호출하지만 글로벌 라우트 하나로 처리한다.
  - BIND+ 안내 POP: 주제 수정·추가와 대화 신청 2곳에서 뜨지만 이동 대상은 `마이 > BIND+` 하나다.
