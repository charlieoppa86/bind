# BIND 정보구조도 (IA)

- 작성일: 2026-11-15 (최종 개정 2026-11-18: 카카오 장소 검색 체크인, 주제·키워드 24개, 탭 이름·순서, 요청 용어, Firebase 연결. 아래 "개정 내역" 참고)
- 근거 문서: BIND 최상위 전략 문서, BIND 사용자 스토리 (Must 12 · Should 7)
- 슬로건: **같은 공간에서 같은 관심사로** / 우리들의 스몰톡, 바인드
- 하단 탭 4개: **체크인 · 채팅 · 요청 · 마이페이지**. 체크인 전에는 체크인 탭 자리에 체크인(장소·주제 입력) 화면이 먼저 열린다. 탭 화면 AppBar 왼쪽에는 BIND 마크가 붙는다.
- POP = 다이얼로그, 시트 = 바텀시트. 둘 다 별도 라우트를 갖지 않는 오버레이는 기능 칸에 적고, 독립 라우트가 필요한 것만 행으로 뺐다.
- 용어: 문서의 "스팟"은 카카오 장소 검색으로 고른 장소다. **같은 카카오 장소 ID**를 고른 사람끼리 같은 스팟 피드를 본다. "요청"은 상대 카드에 보내는 대화 요청이다(예전 "신청").

## Flutter 라우트 매핑

go_router 기준이다. 하단 탭 4개는 `StatefulShellRoute`로 묶고(브랜치 순서 = 탭 순서), 체크인·인증·글로벌 화면은 셸 밖 최상위 라우트로 둔다. 라우트 문자열은 `Routes`(lib/app/router/routes.dart)만 쓴다.

## 누락/중복 검토

- **누락된 스토리: 없음.** Must 12개와 Should 7개가 모두 1개 이상의 경로에 매핑된다.
- **앱 라우트가 없는 스토리: US-018.** 주최자 리포트는 MVP 단계에서 운영자가 이메일로 보낸다. 주최자용 앱 화면이 필요해지면 `운영` 분류를 별도 웹 대시보드로 분리한다.
- **Could 스토리(US-020~023)는 매핑하지 않았다.** 추가할 때 위치는 다음과 같다. US-020 부스트 → 체크인 > 스팟 피드 > 내 체크인. US-021 명함 보내기 → 채팅 > 대화방. US-022 인기 키워드 → 체크인 > 스팟 피드. US-023 주최사 로고 → 체크인 > 스팟 피드 헤더. 새 라우트는 생기지 않는다.
- **중복된 경로: 없음.** 다만 진입점이 여러 개인 화면이 3개 있으며, 모두 의도한 것이다.
  - 사용법 가이드: 온보딩과 마이페이지에 라우트가 2개 있지만 같은 위젯을 재사용한다.
  - 신고·차단: 스팟 피드, 요청 상세, 대화방 3곳에서 호출하지만 글로벌 라우트 하나로 처리한다.
  - BIND+ 준비 중 POP: 마이페이지 카드, 주제 수정·추가, 대화 요청 3곳에서 뜬다(결제 연결 후 이동 대상은 `마이페이지 > BIND+` 하나).
